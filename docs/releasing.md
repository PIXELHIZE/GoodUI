# npm 배포

이 저장소에서는 `pnpm release:plan`으로 변경 없는 배포 계획을 확인하고 `pnpm release:publish`로 게시합니다. npm 계정 로그인·게시 권한이 필요하며 npm이 요구하는 웹 인증은 CLI의 링크에서 완료합니다.

배포기는 빌드·타입·테스트 후 각 패키지를 pack하고, 이미 공개된 버전의 무결성을 모두 사전 확인합니다. 누락된 버전은 `next` 태그로 일괄 게시한 뒤 **공개 설치 metadata와 실제 tarball의 SHA-512**를 확인합니다. 후보 버전의 처리 대기는 병렬로 진행하며 게시 접수나 단일 버전 endpoint만으로 준비됐다고 판단하지 않습니다. 모든 의존성이 준비되기 전에는 후보 버전을 설치 안내에 사용하지 않습니다.

네 버전 모두 다운로드할 수 있을 때 `test:published`의 npm·ESLint 9·10·strict pnpm 검사를 실행합니다. 성공한 후에만 `latest`를 올리며 메인 CLI를 마지막에 처리합니다. 검사 실패 시 최신 태그 승격을 실행하지 않습니다. 공개 처리 대기는 패키지별 최대 15분이며, 시간 초과 시 같은 버전을 다시 게시하지 않고 처리 완료 후 재실행합니다.

패키지마다 다른 버전을 사용할 수 있습니다. 이미 공개한 버전과 pack 결과가 다르면 중단하므로, 소스·문서·포장 내용이 바뀐 패키지는 먼저 버전을 올려야 합니다. 새 main 버전은 초기화 코드가 기대하는 내부 버전을 가리키는지 함께 확인합니다.

`npm publish --tag latest`를 직접 실행하면 이 보호를 우회합니다. 자동 배포에서도 동일한 배포기를 사용하고 토큰·인증 비밀은 저장소에 기록하지 않습니다. npm 게시·dist-tag 인증이 만료되면 npm이 새 인증을 요구할 수 있습니다.
